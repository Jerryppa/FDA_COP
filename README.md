# FDA_COP — continuation decisions

Run shiny::runApp() in this folder. Existing package requirements are unchanged.

Design → Treatment continuation decisions contains two tabs:
- Induction → consolidation: enable the decision and set its time before maintenance.
- Consolidation → maintenance: enable eligibility selection at the existing stage-2 time.

Each tab has an arm-specific conditional continuation probability (0–1), editable continue/stop labels, and a post-stop OS hazard multiplier relative to the stage-1 hazard. Both decisions default OFF; enabling with probability 1 retains everyone still alive and followed. Stop labels describe a combined reason category; individual reasons and clinical response states are not generated by these controls. The existing Truth binary response remains a separate variable assessed at maintenance.

Consolidation is an intermediate pathway, not a third survival-parameter stage. It uses the stage-1 hazard and initial treatment. Patients who stop never receive maintenance; they continue OS follow-up with the specified post-stop hazard until death, independent random censoring, or the administrative cutoff. Initial arm membership remains unchanged for ITT analyses. True survival curves include all stop/continue mixtures. The current gate probabilities are fixed by initial arm, not adjusted for prognostic covariates.

Generated datasets add continued_to_consolidation, continued_to_maintenance, treatment_stop_time, and treatment_stop_decision. NA means the decision was disabled or not reached; FALSE means assessed and stopped. Existing reached_stage2 now means actually reached maintenance after passing enabled decisions.

Validation: all three R files parse; simulation checks cover continuation probabilities 0, 1, and intermediate values, survival after stopping, disabled-control compatibility, and agreement of analytic truth with simulated OS. Full interactive Shiny rendering was not tested in this environment.
